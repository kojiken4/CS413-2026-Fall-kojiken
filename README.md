## Mirroring this repository

Please create a private repository that mirrors this one and update
frequently.

Step 1:

Please clone the class repository:

```
git clone https://github.com/hwxi/CS413-2026-Fall
```

Step 2:

Please create a repository of your own.
For instance, the following one is created
for my own use:

https://github.com/githwxi/CS413-2026-Fall-hwxi

Then please mirror-push the class repo into your own repo:

```
cd CS413-2026-Fall
git push --mirror https://github.com/githwxi/CS413-2026-Fall-hwxi
git clone https://github.com/githwxi/CS413-2026-Fall-hwxi
cd CS413-2026-Fall-hwxi
git remote add upstream https://hwxi@github.com/hwxi/CS413-2026-Fall.git
```

Step 3:

Please remember to sync with the class repo *frequently*:

```
git fetch upstream
git merge upstream/main main
```



# AI Reflection

Having used GPT-6 Astra right after its release in Codex, I found it to be extremely capable, ensuring that it self-validated its own work rigorously before suggesting or making changes to any files it created or modified. The only weakness I would say it had was its token consumption, as it would run through my tokens on my ChatGPT Plus plan in less than 50 prompts using Astra. However, I used this assignment more as an opportunity to try this new model out, so I probably would not have this issue in the future. Moreover, I also had a side chat open in my Codex dashboard running GPT-5.6 Terra for asking quick questions that I wanted to exclude from my main conversation, which helped to reduce my token consumption.

Parsing through the ATS code was very difficult for me, having no prior experience with the language. So I mostly focused my efforts on understanding the functionality of the program as a whole, and then tracing through and understanding line-by-line GPT-6 Astra's implementation of the ATS Eight-queens puzzle program in Python. This was the most helpful part of the process for me, as I was able to understand the functionality of the ATS program using a language I was more familiar with, alongside having the ability to quickly prompt the model on what specific functions or lines did, in terms of its functionality or its syntax.

Before this assignment, I have already seen the benchmarks released for OpenAI's new GPT-6 Astra model. Furthermore, having worked with their latest model in its native Codex harness, and seen the real-world examples of its usage doing agentic work far beyond the scope of this assignment, I found myself being able to trust it and what it outputs pretty easily, reinforced by the fact that no changes were needed to the Python translation of the ATS program it generated. I found that leaving the heavy agentic work to a model like GPT-6 Astra and the quick questions and side comments to a lighter model like GPT-5.6 Sol or Terra was a really good workflow for me, balancing both capability and token usage.

Overall, this AI workflow greatly reduced the amount of work I had to do manually, as well as the time it took to understand programs and code written/generated by others. However, it was really important to me that I understood its outputs so as to keep me in the loop of things and letting me have agency over its actions, rather than having AI blindly handle the whole process. The only real work I had to do in this case was writing the markdown files containing the AI transcript, repository model instructions, and editing this README, as well as unit tests and most of the test script, with its functionality also verified by AI.
